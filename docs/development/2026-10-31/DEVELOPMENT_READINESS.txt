6. 착수할 구현 순서 — 개발 제안, 이번에 구현하지 않음
1) 원문은 보존하고 검색용 항목을 별도로 만든다. 근거 파일/행·조항, 대상, 시행/신고/주문 기준, 확정/진술/철회/상충, 공개범위, 필수 조회, 권한, 기대 결과를 연결한다. 후속 정정은 기존 항목과 연결해 폐기된 근거 검색을 막는다.
2) 공통 정책과 문의별 필요한 분야만 모델에 공급한다. 날짜·인증/귀속·개인정보·권한·결과 확인은 모든 경로에 적용한다. 금액·기한·한도는 검증된 규칙/원장으로 계산한다.
3) 문의→인증/귀속→필수 근거 조회→시점/조건 판단→고객 선택/승인→실행→상태 확인→응답 흐름을 만든다. 조회 실패·기록 없음·미연결·승인 대기·실패·결과 불명을 구분한다.
4) API 미제공 구간은 명시적인 모의 결과로 개발한다. 실제 명세 수령 후 액션별 validate/authorize/execute와 성공 판정을 연결한다. 모의 이관/환불을 실제 완료로 표시하지 않는다.
5) 배송 변경/취소, 하자·C31, 가격 개정·과거 경험, 제3자 정보 보호, 정기배송, 결제 대사·증빙, 체험·회원·프로모션 순으로 대표 경로를 검증한다. 순서는 개발 제안이며 출제 비중을 추정한 것이 아니다.
6) 정확도와 필수 액션을 먼저 검증하고 이후 호출 수·말풍선·글자 수·p95를 측정해 줄인다.

7. 완료 판단 기준
필수 업무마다 원문→판단→필수 조회/쓰기/이관→응답 기대값을 추적할 수 있어야 한다.
대표 정상·거절·정보 부족·권한 초과·상충·구판/개정·타임아웃·중복·재개 사례를 실행한다.
C31은 정상 인계만 보고 정상 운송 결론 금지, 늦은 하자 접수는 각하 금지, 과거 현금 보상은 새 주문 현금 권리로 확대 금지, 타인 주문은 정보 노출 금지를 확인한다.
499/500/501자·이모지·가림 후 길이, 오류/제한 응답, 10번째 말풍선·60초 무응답 경계, 케이스 간 분리·재개, 실제 API 결과와 카카오 답변 일치를 확인한다.
현재 정적 수용 사례의 작성 수를 실행 통과 수나 개발 완성률로 사용하지 않는다.
제출 여부는 이번에 확인하지 않았다. 기존 제출본 변경 금지·운영 유지 방침을 적용하며, 이 검토로 운영 코드·런타임 프롬프트·배포를 변경하지 않았다.
