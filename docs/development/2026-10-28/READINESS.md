## 완료한 연결

- 이 프로젝트의 `src/worker.mjs` → `runAgent` → OpenAI Responses API(`gpt-6-luna`) → 카카오 콜백을 연결했다.
- SQLite 기반 Durable Objects 두 종류를 실제 생성·배포했다. Conversation은 채팅방+사용자별 대화와 이벤트를, UsageBudget은 봇 전체 모델 호출량을 관리한다.
- 사용자가 실제 카카오톡에서 부산·3일 여행 조건을 전달한 후 다음 메시지로 목적지와 기간을 물어 정상 기억 답장을 확인했다.
- 이전 별도 폴더의 단일 메시지 Worker는 과거 버전이다. 앞으로는 **현재 프로젝트 루트의 wrangler.jsonc**로 배포한다.
- 대회 액션 목록은 아직 비어 있다. 외부 업무가 실행됐다고 주장하지 않도록 지침을 적용했다. 당일 사양 공개 후 도구를 등록한다.

## 보관·중복·오류 처리

- 대화 요약 최대 600자, 마지막 갱신 후 30분. 원문 메시지·최종 답변 전문·콜백 토큰·서버 키를 DB에 저장하지 않는다. 모델에 요약 생성을 지시하고, 알려진 비밀값·키 패턴·이메일·전화번호를 제거한다. 임의 개인정보 전부를 완벽히 식별하는 기능은 아니다.
- `/초기화`는 대화 요약만 삭제한다. 중복 방지 기록은 지우지 않는다.
- 메시지 ID는 64비트 숫자 정밀도 손실 없이 읽어 해시로 보관한다. 같은 이벤트의 처리·콜백 시도 기록은 24시간 유지한다.
- 같은 채팅방이라도 사용자가 다르면 분리한다. 동시 요청은 사용자별 순서대로 처리하며 실행 중+대기 최대 2건, 추가 요청은 안내한다.
- 쓰기 도구·인자의 해시를 실행 전에 영구 기록한다. 동일 쓰기 재시도는 거부하며, 결과가 불확실한 쓰기가 남으면 해당 사용자의 이후 쓰기를 잠근다. 원본 인자는 DB에 보관하지 않는다. 확실한 미실행만 rejected로 바꾼다. 이 기록도 24시간 보존한다.
- 콜백 시도 전에 영구 기록한다. 전송 결과가 불확실하면 콜백·모델·액션을 자동 재시도하지 않는다.
- 웹훅 비밀값을 HMAC 검증으로 비교한다. 외부 통신은 지정된 HTTPS 목적지로만 하며 리다이렉트는 따라가지 않고 비정상 상태로 처리한다.
- 로그에는 성공 여부·모델 호출 수·토큰 수만 기록한다. 사용자 내용·식별자·토큰은 기록하지 않는다.

## 시간과 호출 제한

[카카오 웹훅 문서](https://developers.kakao.com/docs/ko/bot/webhook)와 [이벤트 규격](https://developers.kakao.com/docs/ko/bot/gateway#message-create)을 로그인 상태에서 확인했다. 수신 확인은 1초 이내, 콜백 토큰은 5분 유효다.

- 웹훅은 인증·검증 후 204를 반환하고 처리는 waitUntil로 넘긴다. 실제 1초 이내 수신 확인은 모든 네트워크 상황에 대해 보장한 것이 아니다.
- 에이전트 최대 18초, 큐 대기를 포함한 모델 처리 기한은 수신 후 24초, 콜백 최대 4.5초. 모델 호출 단계 최대 4회. 대기 시간이 길면 실행하지 않고 안내한다.
- 연습용 자체 제한: 사용자별 60초 창에 메시지 10건, 봇 전체 60초 창에 모델 호출 60회·24시간 창에 2,000회. 공급자 리셋 시간과 다른, 첫 호출에서 시작하는 자체 시간 창이다.
- 한 번의 모델 출력은 최대 1,400토큰. 직렬화 요청은 32,000자 이하. 한 사용자 입력은 4,000자 이하.
- 자체 한도를 초과하면 새로운 모델 호출을 중단한다. 계정 전체의 다른 앱 비용까지 제한하는 기능은 아니다. 심사 예상량을 확인한 뒤 제출 전에 재조정한다.

## 비용·무료 한도 판단

[Luna 공식 가격](https://developers.openai.com/api/docs/models/gpt-6-luna): 짧은 문맥 Standard 기준 입력 100만 토큰 $0.10, 출력 $0.50. 프로젝트 기본 서비스 계층은 Standard로 확인했다.

실제 로컬 기억 테스트 2회는 입력 총 718토큰·출력 83토큰이었다. 도구 왕복 테스트는 모델 호출 2회, 입력 1,027·출력 49토큰이었다. 대회 문제의 토큰 사용량을 대표하지는 않는다.

계획 예시: 모델 호출당 입력 1,000·출력 300토큰이면 호출당 약 $0.00025, 하루 2,000회면 $0.50, 7일이면 $3.50이다. 도구 1회 후 답하는 경우 보통 모델 호출 2회가 필요하므로 사용자 메시지 수와 모델 호출 수를 구분한다. 긴 문맥·여러 도구·다른 앱 사용에 따라 실제 비용은 달라진다.

[Cloudflare 공식 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/): Free에서 DO 요청 100,000/일, 실행 13,000 GB-s/일, SQL 읽기 500만 행/일·쓰기 10만 행/일, 저장 5GB. 무료 일일 한도는 한국시간 09:00 리셋이다. 초과 시 오류가 발생한다.

현재 정상 메시지는 Conversation 요청 1회와 모델 호출당 UsageBudget 요청 1회가 기본이며 정리용 알람 요청이 추가된다. SQL 작업에는 인덱스·정리·알람 쓰기가 포함되므로 단순 메시지 수만으로 과금 행 수를 확정하지 않는다. 예시로 하루 2,000건이 각각 18초 활성화되면 Conversation 계산 시간은 약 4,608 GB-s(128MB 가정)이다. 오류·대기·다른 객체·다른 서비스 사용량은 별도다. 실제 심사 트래픽의 최대치가 공개되지 않아 전체 심사 처리량 보장은 하지 않는다.

## 검증 근거

1. 기존 93개 및 신규 16개: 총 109개 Node 테스트 통과.
2. workerd + 실제 SQLite DO 모의 실행: 4번 전달(동일 이벤트 포함)에 모델 3회·콜백 3회, 같은 사용자 요약 재사용·다른 사용자 격리 확인.
3. workerd 검사에서 redirect:error 미지원 발견 후 manual+상태 검사로 수정, 재검증 통과.
4. 실제 Luna: 다중 턴 요약 기억 성공. 모의 조회 도구를 실제 모델이 1회 선택하고 결과 코드 BUSAN-TEST-42를 답하는 왕복 성공. 대회 API 호출이 아님.
5. 실제 Cloudflare 배포 및 health 응답: agent-practice / gpt-6-luna / memoryMinutes 30 / configured true.
6. 사용자의 실제 카카오톡 다중 턴 테스트 성공 보고.
