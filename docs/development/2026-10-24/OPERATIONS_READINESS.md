# 운영 유지·Durable Objects 요금 및 계정 확인

확인일: 2026-10-24(한국시간)  
기준 결정: `docs/verification/2026-10-24/DECISIONS.md` D-01·D-02 및 총괄자의 직접 확인  
방법: 공식 문서 조회와 현재 로그인된 Cloudflare·OpenAI 계정 화면의 읽기 전용 확인

## 1. 확정된 운영 기준

- 정상 운영 유지와 제출본 변경·삭제 금지: **2026-11-03 24:00 KST(11-04 00:00)**까지.
- 저장소: **Cloudflare Durable Objects**. KV로 대체하지 않는다.
- 순서: **V-001 검증·권한 엄격 판정 → V-002 중복 쓰기 차단**을 우선하며, 안전한 결과 분류·처리에 필요한 보완을 연결한 뒤 저장소를 구현한다.
- 11/3 종료 시각은 총괄자의 운영 결정이다. 운영사무국이 공식 상세 규정을 변경했다고 표현하지 않는다.

## 2. 실제 계정에서 확인한 사실

|대상|현재 화면의 확인 내용|판정|
|---|---|---|
|Cloudflare 구독|Workers Free, Active|SQLite 기반 Durable Objects 지원 플랜에 해당|
|Cloudflare 결제|등록된 결제 수단 없음|유료 업그레이드는 적용하지 않음|
|Durable Objects 화면|객체 없음, 요청·Duration·SQL 저장 사용량 표시 0|아직 이 저장소를 생성·배포하지 않음|
|OpenAI API 결제|Free trial, Credit remaining $0.00|현재 모델 운영 자금 준비 미완료|
|OpenAI 결제 수단|아직 결제 플랜을 시작하지 않았다는 안내|유료 API 사용 설정 필요|
|OpenAI 사용 계층|Free tier|현재 한도가 대회 트래픽에 충분한지 보장할 수 없음|
|OpenAI 키 목록|활성 키 2개, 둘 다 만료 안 함, Default project|표시된 키 자체의 예약 만료는 없음. 대회 서버에서 사용할 키인지 미확인|

API 키의 실제 값은 수집하지 않았다. 목록에 키가 있다는 사실은 로컬 보관 여부·서버 설정·호출 성공의 증거가 아니다. 확인한 OpenAI Personal 조직 이외에 별도 결제 조직을 사용할 경우 해당 조직을 다시 확인해야 한다.

화면 확인 위치:

- Cloudflare 계정의 Manage account → Billing → Subscriptions
- Compute → Durable Objects
- OpenAI Platform → Organization → Billing, Limits, API keys

## 3. Durable Objects 지원과 비용

**현재 Free 플랜에서 SQLite 기반 Durable Objects를 사용할 수 있다.** 새 저장소는 SQLite 기반으로 구성한다. 실제 마이그레이션·배포 성공 여부는 P0 보완 후 확인할 사항이다.

|사용량|Workers Free 포함량|Workers Paid 포함량 및 초과 단가|
|---|---|---|
|DO 요청|100,000/일|100만/월, 초과 100만 단위 $0.15|
|DO 실행 시간|13,000 GB-s/일|400,000 GB-s/월, 초과 100만 단위 $12.50|
|SQL 읽기 행|500만/일|250억/월, 초과 100만 행 $0.001|
|SQL 쓰기 행|10만/일|5,000만/월, 초과 100만 행 $1.00|
|SQL 저장|총 5GB|5GB-month, 초과 $0.20/GB-month|

Free는 한도 이내면 추가 요금 $0이며, 초과 시 자동 유료 처리 대신 해당 작업이 오류로 실패한다. 일별 한도는 UTC 00:00, 즉 한국시간 09:00에 초기화된다. 요청·행·시간은 서로 다른 계량이며 다른 작업의 사용량도 함께 고려한다. [공식 Durable Objects 요금](https://developers.cloudflare.com/durable-objects/platform/pricing/)

Workers Paid 기본료는 월 최소 $5이며 포함량 초과 비용이 추가된다. 현재 계정은 Free로 유지했다. 며칠만 운영한다는 이유로 월 기본료가 일할 계산된다고 가정하지 않는다. Workers 자체 요청·CPU와 모델 비용도 별개다. [공식 Workers 요금](https://developers.cloudflare.com/workers/platform/pricing/)

**현재 요금제에서 기능 사용은 가능하지만, 알려지지 않은 심사 요청량 전체를 Free 한도 안에서 처리할 수 있다고 확정할 수는 없다.** 메시지당 DO 호출·SQL 행·활성 시간을 측정한 후 판단한다. 모델을 기다리는 동안 객체가 활성 상태면 실행 시간 계량에 영향을 주므로, 저장소를 짧게 사용하더라도 동시성·중복 방지의 정확성이 유지되는 설계를 검토한다.

## 4. 모델 사용량·결제 확인

현재 계정 화면에서 확인한 예:

|모델 표시|요청 한도|토큰 한도|
|---|---|---|
|gpt-6-astra / gpt-6.1-sol|3 RPM, 50 RPD|10,000 TPM|
|gpt-6-luna|10 RPM, 50 RPD|60,000 TPM|

이는 계정 화면 관찰이며 모델 선택 권고가 아니다. 대회용 모델은 아직 확정·연결하지 않았다. 한 사용자 메시지에도 도구 처리 후 재호출 등 여러 모델 요청이 필요하므로, 메시지 수만으로 API 요청량을 계산하면 안 된다.

월 사용 승인 한도, 조직·프로젝트 지출 한도, 선불 잔액, RPM/RPD/TPM은 별개다. 경고 알림은 요청을 중단하지 않지만 적용 중인 강제 지출 한도는 요청을 막을 수 있다. 현재 결제 미시작 상태에서 미래 결제 한도 값을 추정하지 않았다. [공식 호출 한도 안내](https://developers.openai.com/api/docs/guides/rate-limits), [공식 지출 한도 안내](https://developers.openai.com/api/docs/guides/spend-limits)

현시점 판정: **키 목록의 예약 만료 문제는 보이지 않지만, 잔액 $0·결제 미설정 때문에 11/3까지 모델 운영 가능 판정을 내릴 수 없다.** 실제 서비스에 사용할 키·프로젝트를 확인하고 결제·잔액·모델 한도를 준비한 후 다시 점검해야 한다. 키 발급·결제 등록·충전·요금제 변경은 이번 조회에서 수행하지 않았다.

## 5. 실제 운영 가능 판정에 필요한 추가 확인

- [ ] 실제 사용할 OpenAI 조직·프로젝트·모델·서버 키 연결 확인
- [ ] 해당 키의 활성 상태·만료일이 11/4 00:00 KST 이후인지 확인
- [ ] 실제 API 결제 시작, 잔액 및 크레딧 만료·충전 정책 확인
- [ ] 조직·프로젝트 강제 지출 한도와 승인 사용 한도 확인
- [ ] 10월 31일 및 11월 1~3일의 사용량·결제 주기와 리셋 기준 확인
- [ ] 예상 심사 대화 수 × 대화당 모델 호출 수·입출력 토큰으로 예산 산정
- [ ] 호출 급증을 포함한 모델 RPM/RPD/TPM 여유 확보
- [ ] 메시지당 DO 요청·행·활성 시간과 계정 전체 사용량 측정
- [ ] 필요 시 유료 플랜·충전의 비용과 설정을 총괄자에게 제시해 결정
- [ ] 대회 전 실제 왕복 호출·사용량 표시 확인, 제출 직전 재확인

미래의 장애·추가 트래픽·결제 거절까지 보장할 수는 없다. 이번에 확인한 상태와 미확인 조건을 구분하고, 운영 중단을 예방할 설정은 제출 전에 완료한다. 이번 작업으로 자동 감시·충전·예약 실행은 생성하지 않았다.

## 6. 저장소 구현 시 주의점과 인계

Durable Objects를 선택했다는 사실만으로 외부 쓰기의 정확히 1회 실행이 보장되지는 않는다. 비동기 I/O 중 요청이 섞일 수 있는 구간, 이벤트 처리 상태의 원자적 전이, 외부 API 실행 후 저장 실패·콜백 실패를 별도로 설계·검증한다.

총괄자 결정 D-02의 상태·이벤트·최근 쓰기 기록을 사용자/채널별로 분리하고, 보존 기간은 결정 기록의 예시와 확정 정책을 구분해 정한다. P0 로컬 차단을 먼저 완성하고 여러 메시지·중복 이벤트의 저장 기반 차단은 그다음 단계로 검증한다.

이번 변경은 결정 반영과 읽기 전용 요금·계정 확인이다. 소스·테스트·배포·실제 결제·키 설정은 변경하지 않았다. 검증 담당의 보고서와 결정 원본도 수정하지 않았다.
