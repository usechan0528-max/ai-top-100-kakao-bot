# 결제·주문 대사 절차

### 1. 대사 키

네 가지 대사 키를 모두 대조한다. 일부 항목의 일치만으로 동일 결제로 확정하지 않는다.

|키|허용 오차|확인 출처|없으면|
|---|---|---|---|
|승인번호|정확 일치|결제 승인 내역|대사 불가 → §3 M-03|
|결제금액|정확 일치 (실결제액 기준)|결제 승인 내역 ↔ 주문|§3 M-04|
|승인시각|±5분|결제 승인 내역 ↔ 주문 생성 시각|§3 M-05|
|카드 뒷 4자리|정확 일치|결제 승인 내역 ↔ 고객 제시분|§3 M-06|

결제 승인과 주문 레코드 생성 사이의 정상적인 지연을 고려하여 승인시각의 허용 오차를 ±5분으로 적용한다. 초 단위 일치를 요구하거나 허용 오차를 임의로 확대하지 않는다.

결제금액은 실결제액이다 — 정가·할인 전 금액이 아니라 카드·포인트·쿠폰 분할 구성의 합, 곧 실제로 받은 금액이다. 분할결제 건은 카드분만 따로 대사하지 않는다.

### 2. 절차

|순|무엇|도구|
|---|---|---|
|(1)|결제 승인 내역 조회 — 승인번호·금액·승인시각·카드 뒷 4자리를 확보|시스템 조회|
|(2)|주문 대조 — 같은 고객·같은 시각대의 주문 레코드를 §1 네 키로 맞춘다|시스템 조회|
|(3)|판정 — §3 표에서 유형을 고른다|—|
|(4)|처리 — 주문 복구 / 미배송분 환불 / 결제사 조회 접수 중 하나|§4|
|(5)|안내 — 어느 유형이었는지 · 무엇을 처리했는지 · 반영에 걸리는 기간을 함께 말한다|§6|

(1) 결제 승인 내역 조회와 (2) 주문 대조를 모두 수행한다. 어느 한쪽의 조회를 누락한 상태에서 환불 불가 또는 중복 결제로 판정하지 않는다.

조회 없이 "주문 없음"으로 종결하지 않는다. 고객이 받은 결제 문자는 결제가 일어났다는 신호이고, 주문 조회의 "해당 주문 없음"은 조회가 성공했다는 뜻일 뿐 결제 사실을 부정하는 값이 아니다.

|M-10|네 키 전부 일치 · 주문이 다른 계정에 있음|계정 귀속 문제|계정 명의를 확인하고 본인 건만 처리한다 (「조합 규정집」 제8조). 타 계정 주문의 존재·내용을 알려주지 않는다|

M-09를 M-01로 오처리하면 정상 주문을 환불한다. 조회가 "없음"을 반환한 것과 아직 반영되지 않은 것은 다르므로, 승인 직후 건은 M-01로 확정하기 전에 재조회 한 번을 거친다. 재조회 간격·횟수 상한은 「운영 한도 스펙(페일·조회 상한·폴링·재시도·멱등·동시성·토큰 예산)」 LIM-08이다. 생성 실패 상태의 주문 레코드가 조회되면 그것으로 M-01이 확정된다 — 실패 기록이 있으면 지연(M-09)이 아니다.

M-01 주문 유실을 M-08 중복 결제로 판정하여 환불만 처리하지 않도록 유의한다. 주문이 조회되지 않는다는 사실만으로 중복 결제로 확정하지 않으며, 유실된 주문의 복구 가능 여부를 확인한다. 중복 결제는 결제 승인이 2건일 때만 성립한다.

### 4. 주문 복구 및 환불 기준

M-01이 확정된 경우 유효한 결제와 고객의 구매 의사에 따라 주문 복구를 원칙으로 한다.

|조건|처리|
|---|---|
|상품 확보 가능 + 출하 가능|주문 복구 — 결제 내역을 원본으로 주문을 재생성하고 정상 출하|
|품절·시즌 종료로 출하 불가|미배송분 환불 (전액)|
|지연으로 고객이 더는 원하지 않음|미배송분 환불 — 고객 의사를 우선한다|
|일부만 출하 가능|출하분 유지 + 미배송분만 환불 (부분)|

환불 기준액도 실결제액이다(§1과 같은 기준). 복구 시에는 추가 결제를 요구하지 않는다 — 가격이 그 사이 올랐어도 결제된 금액대로 출하한다.

주문 유실에 대한 처리 책임은 조합에 있다. 기존 결제에 대한 복구 또는 환불 처리를 완료하여야 하며, 고객에게 재주문만 요청하고 종결하지 않는다.
