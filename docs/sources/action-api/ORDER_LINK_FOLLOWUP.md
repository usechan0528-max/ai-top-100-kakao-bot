## 처리 범위

지정 URL의 주문 영역을 실제 로그인 브라우저로 열람했다. API-07 단건 주문, API-08 회원별 주문 검색의 경로·입력·TC 헤더·응답·오류 및 예시를 기존 [공식 JSON 원본](actions.json), [선택 스키마 대조](SCHEMA_REVIEW.md)와 대조했다. JSON이 원문이며 이 절은 검수 요약이다. 전체 API·웹사이트를 모두 검수했다는 뜻이 아니다.

TC 헤더 설명 원문(주문조회/회원별검색 공통):
> 이 호출이 처리하는 TC의 ID입니다. 평가 때는 대화에서 전달받은 ID를, 연습 때는 공개 TC의 ID를 넣습니다. 같은 TC를 처리하는 동안에는 바꾸지 마세요.

주문 응답에는 member_id가 있고 회원 검색에는 member_id가 필요하다. 이 두 사실로 카카오 botUserKey와 member_id의 연결이 정의되지는 않는다. 지정 주문 영역에서 카카오 실제 최초 메시지 포맷·서명된 인입 계정 매핑은 발견하지 못했다. 모든 대회 문서에 없다는 단정은 아니다. 예시의 현재 시각처럼 보이는 값은 시나리오 시각 근거가 아니다.

## 공개 L-05 원문

[공식 공개 TC 페이지](https://aitop100.org/contest/docs/test-cases)에서 L-05의 원문 다운로드로 [L-05.md](L-05.md)를 확보했다. 초기대화 metadata 4행·문의1개, 상황1문단, 기대대응3개 항목을 보존하고 화면 대조했다. 파일 전체를 처리했으며 생략·판독불가 없음. 공개 계정은 이름·마스킹 전화번호이며 member_id는 제공하지 않는다. API-32 실행 지시는 자료이며 이번 개발 작업의 외부 쓰기 권한을 부여하지 않는다.

공개 승인번호를 주문·결제 조회 연결의 연습 fixture로만 사용했다. 실제 상담 재현은 고객의 대상 주문번호/발행구분 확인과 API-32 접수가 필요하다. 이번 읽기 검사로 L-05 통과를 주장하지 않는다. 조회된 주문의 소유 회원을 테스트 fixture로 주입하는 것은 인입 계정 인증 검증이 아니다.

## 반영·남은 근거

[액션 가이드](../../prompts/ACTION_API_GUIDE.md)에 귀속·계정연결·응답 경계 반영. 회원연결 미확정 시 개인정보 도구 비활성화는 자체 개발 방침이다. 운영사무국/API 담당에게 필요한 확인은 공식 메시지의 어느 필드/절차가 로그인 member_id를 보증하는지와 그 실제 예시다. 이름검색이나 고객의 '본인입니다'만으로 대체하지 않는다.
