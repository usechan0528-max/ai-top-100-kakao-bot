# 제출 전 잔여 기능 정리·우선 구현 요청 원문

자료 기준일·수신일: 2026-10-31. 시나리오 현재 날짜2037-06-30과 구분한다.
출처: 현재 Codex 채팅의 사용자 직접 요청. 이 파일에는 전달된 원문을 그대로 보존하며 아래 개발 해석과 구분한다.

## U01 — 사용자 원문

> 그럼 다른 채팅에서 진행 중인 작업까지 합쳐서 제출 전 남은 미구현 기능과 검증 항목을 정리하고, 우선순위 높은 것부터 계속 진행해줘.

## 처리·대조 기록

텍스트1문장 전체 보존. 첨부·압축파일·신규 다운로드 없음. 요청의 두 요소인 다른 채팅 작업을 포함한 잔여 기능/검증 정리와 높은 우선순위 구현 계속을 대조했다. 기존 공식 actions.json과 공개15TC/73기대항목의 검수 자료를 재사용하며 신규 원문 전사나 전체 시나리오 실행 합격으로 표현하지 않는다.

현재 후속 구현: 상품/로트/조사/신고집계/프로모션 조회5개 및 재배송/쿠폰발급/출고일정변경 접수3개를 별도 모듈로 작성·모의검증했다. [조회 범위](../../development/2026-10-31/CATALOG_QUALITY_ACTION_SCOPE.txt)·[접수 범위](../../development/2026-10-31/FULFILLMENT_REQUEST_SCOPE.txt). 이 기록 시점에는 새8도구의 공유 런타임 등록·배포·실제 API 검증은 미완료다. 다른 채팅의 이미 완료한 기능과 섞어 전체 기능 완료로 보고하지 않는다.

권한/추가 정보: 모델의 확인 플래그는 독립 인증/승인이 아니며 전체 보상쿠폰표·기간/날짜 판단·정식 승인 경계는 필요한 근거를 별도로 확인한다. 최신 질문 전달 방식은 [사용자 직접 전달 정정](../../BUSINESS_CONTEXT.md#질문-전달-담당-변경--2026-10-31)을 따른다. 질문 대상·문구를 사용자에게 전달하며 에이전트의 카카오톡 직접 메시지 지시를 새로 만들지 않는다.

반영 위치: ACTION_API_GUIDE, PUBLIC_TC_GUIDE, 생산/배송/환불/홍보/회원/권한 분야 가이드, 두 색인, BUSINESS_CONTEXT의 2026-10-31 제출 전 우선 구현 후속 절. 원문1항 누락 없음. 런타임 연결/예산/최종 접수 응답 통합은 담당자의 후속 증빙으로 추가한다.
