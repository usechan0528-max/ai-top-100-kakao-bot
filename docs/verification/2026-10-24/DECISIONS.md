## D-01. 심사 기간 운영 유지와 변경 금지의 종료 시점

**결정: 운영사무국 확인 전까지, 정상 운영 유지와 제출본 변경·삭제 금지를 2026-11-03 24:00(11-04 00:00) KST까지 지킨다.**

- 배경: 총괄자가 전달한 상세 안내는 2026-11-01 24:00, 공식 홈페이지 일반 일정은 10/31~11/3 (`docs/DOTS_RULES_CHECK.md` 6장)
- 이유: 늦은 시각을 따르면 두 안내를 모두 지킨다. 반대로 이른 시각을 따랐는데 실제 심사가 11/3까지라면 서버 중단이나 변경이 규정 위반·심사 실패로 이어진다. 비용은 Cloudflare·모델 사용료 이틀분 정도로 제한적이다
- 성격: 안전한 쪽을 택한 운영 결정이며 규정 해석이 아니다
- 후속:
  - 운영사무국 문의 초안(`DOTS_RULES_CHECK.md` 7장)의 발송 여부는 총괄자가 결정한다. 답변을 받으면 이 결정을 갱신한다
  - 심사가 먼저 끝나 봇·채널이 삭제되면 그 시점에 따른다(체크리스트 기재 사항)
  - 11/2~11/3 사이 모델 API 키 만료, 사용량 한도, 결제 한도에 걸리지 않는지 개발 담당이 제출 전에 확인한다

## D-02. 대화 상태·중복 이벤트 저장소

**결정: Cloudflare Durable Objects를 사용한다. KV는 이 용도로 쓰지 않는다.**

- 용도: (1) 사용자별 짧은 대화 맥락(되묻기 → 다음 메시지), (2) 이벤트 ID 기준 중복 처리 방지, (3) 메시지 간 쓰기 재실행 방지에 필요한 최근 쓰기 기록
- 이유:
  - 같은 사용자의 요청을 한 객체가 순서대로 처리하므로, 동시에 들어온 메시지와 중복 이벤트를 원자적으로 걸러 낼 수 있다
  - KV는 최종 일관성 저장소라 방금 쓴 값이 다른 위치에서 바로 보이지 않을 수 있다. 중복 차단과 "방금 실행한 쓰기" 확인에 부적합하다
- 범위 제한(검증 담당 권고):
  - 사용자(또는 사용자+채널) 단위로 객체를 나눈다. 다른 사용자 데이터가 섞이지 않게 한다
  - 맥락은 최근 몇 턴의 요약·필요 필드만 보관하고 만료 시간을 둔다(예: 30분). 메시지 원문 전체, 토큰, 비밀값은 저장하지 않는다
  - 이벤트 ID 기록은 짧은 보존 기간(예: 24시간)
- **개발 담당 확인 필요(미확인 사실)**: 현재 Cloudflare 요금제에서 Durable Objects 사용 가능 여부와 비용, 무료 플랜 제공 범위. 검증 담당은 공식 문서를 이번에 확인하지 않았다. 사용할 수 없거나 비용이 맞지 않으면 개발 담당이 대안과 영향을 총괄자에게 다시 올린다
- 일정 판단: 구현 규모가 크므로 REVIEW_TASKS의 P0 수정(엄격 판정·쓰기 차단)보다 뒤에 둔다. 대회 전까지 완성하지 못하면 "되묻기 후 맥락 유지 미지원"을 디브리프에 그대로 적는다
