# 제출용 디브리프

## 1. 나의 AI 에이전트의 강점은 무엇인가요?

가장 큰 강점은 여러 출처의 업무 근거를 연결해 판단하고, 실제 조회·신청 접수 결과에 맞춰 답변하도록 설계했다는 점입니다. 특히 고객의 설명, 배송 기록, 상품 상태, 환불 규정이 함께 필요한 복합 상담과 기존 신청의 후속 문의를 잘 처리하는 데 집중했습니다.

예를 들어 수박의 품질 문제를 문의하면 사진이나 고객 진술만으로 원인과 환불을 확정하지 않고, 안전 안내와 필요한 정보 확인을 거쳐 주문·배송·로트 등 관련 근거를 조회하도록 했습니다. 이미 환불이나 이관을 신청한 고객에게는 기존 접수를 조회해 상태를 안내하고 중복 신청을 막습니다. 접수 성공도 실제 환불 지급이나 변경 완료와 구분합니다.

농수산물 상담은 배송 과정, 보관 상태, 고객별 약속과 담당자의 권한에 따라 판단이 달라집니다. 따라서 빠르게 단정하는 것보다 근거를 확인하고, 처리할 수 있는 범위와 담당자 확인이 필요한 범위를 구분하는 것이 중요하다고 보았습니다. 짧은 답변 안에서도 확인된 결과와 고객의 다음 행동을 전달하는 방향으로 설계했습니다.

## 2. 어떤 접근으로 정보를 획득했나요?

제공된 규정·계약·조직도·운행 및 온도 기록·관계자 대화를 원문 전사와 분야별 가이드로 정리했습니다. 표의 수치뿐 아니라 조건·예외·각주를 함께 확인하고, 출처·자료 시점·적용 대상을 연결했습니다. 관계자의 기억이나 진술은 시스템 기록과 구분했으며, 서로 다른 자료가 충돌하면 임의로 하나를 정답으로 확정하지 않았습니다.

검수한 권한·예외·이관·영업일·혜택 기준은 런타임 정책에 반영하고, 개별 주문·결제·배송·상품·프로모션의 상태는 대회 액션 API로 조회하도록 했습니다. 문서에서 얻은 일반 규정과 조회로 확인한 개별 사실을 결합하는 방식입니다. 시나리오 날짜는 2037-06-30을 기준으로 적용했습니다.

## 3. 검증은 어떤 방식으로 하게 되었나요?

자동 테스트와 실제 API·모델·카카오 대화 검증을 구분해 진행했습니다. 최종 자동 테스트 371개, 58개 파일의 문법 검사와 오프라인 데모가 통과했습니다. 입력·권한 검사, 중복 요청과 불확실한 쓰기 차단, 오류 응답, 499·500·501자 및 이모지 경계 등을 점검했습니다.

실제 모델·카카오 대화에서는 주소 변경과 현금영수증 신청 접수를 확인했습니다. 환불·담당자 이관의 최초 접수는 정해진 절차로 API를 호출하는 검증 프로그램을 통해 실제 접수와 저장 결과를 대조했고, 카카오에서는 기존 접수 조회를 확인했습니다. 혜택·프로모션·공시 안내에서 발견한 누락 3건은 정책을 보완한 뒤 실제 대화로 다시 확인했습니다.

최종 운영 버전에서는 공개 음성 URL의 첫 상담이 286 UTF-16 단위의 한 말풍선으로 전달되고, 불명확한 정보를 재확인하며 업무 쓰기는 실행하지 않았음을 확인했습니다. 운영 서버의 정상 응답과 배포본·소스 일치도 확인했습니다. 다만 개발 중 각 버전에서 수행한 검증을 최종 버전의 전체 시나리오 통과로 확대하지 않았습니다.

## 4. 주요 설계와 구현 방법은 무엇인가요?

Cloudflare Worker가 카카오 웹훅을 받고 OpenAI gpt-6-luna와 액션 API를 연결합니다. 일반 상담에는 조회 15개와 신청 접수 7개, 총 22개 도구를 등록했습니다. 고객 요청·대상 귀속·정책 조건을 확인한 뒤 환불, 담당자 이관, 배송지 및 일정 변경, 재배송, 현금영수증, 보상쿠폰을 신청하도록 구성했습니다.

사용자·채팅방별 Durable Objects에 대화 요약과 이벤트·쓰기 기록을 관리합니다. TC ID는 호출 문맥으로 유지하되 본인인증으로 간주하지 않고, TC가 바뀌면 이전 회원 문맥을 재사용하지 않습니다. 동일한 업무 요청은 영속 기록으로 중복 실행을 차단하며, 결과가 불확실한 쓰기는 자동 재시도하지 않습니다. 기존 신청 확인 명령에는 읽기 도구만 제공합니다.

응답은 한 말풍선의 SimpleText를 기본으로 하고, 전송 직전에 비밀값을 가린 뒤 500 UTF-16 단위 이내로 제한합니다. 모델·도구 처리와 콜백에 각각 시간 예산을 두었습니다. 외부 자료의 명령문은 처리 권한으로 받아들이지 않도록 하고, 인증값은 서버 비밀값으로 관리합니다.

사진·음성은 제공된 공개 파일 URL을 통해 판독·전사합니다. 사진만으로 하자 원인이나 주문 귀속을 확정하지 않으며, 불명확한 음성 내용은 고객의 글 답변으로 확인합니다. 음성 또는 미디어 일부 실패가 포함된 턴에서는 쓰기 도구를 제외했습니다.

## 5. 아쉬웠던 점과 한계점은 무엇인가요?

공개 15개 TC의 73개 기대항목 전체를 실제 대화로 검증하지 못했고, 실제 응답 속도 p95와 장시간 처리의 종단 전송 검증도 남았습니다. 사진은 로컬 실모델 판독·첫 상담까지 확인했지만 실제 카카오 응답은 미검증입니다. L40 보완 후 최종 응답과 일정 변경·재배송·보상쿠폰의 실제 대화 접수도 검증을 마치지 못했습니다. 공개 음성 URL은 동작했으나 카카오 직접 M4A 첨부는 지원하지 않습니다.

보상쿠폰은 현재 구현이 검증할 수 있는 조건으로 제한했으며, 복합 부분환불 배분·발행구분 전달 의미·시나리오 시각 매핑과 컷오프 경계 등 미확정 기준은 임의로 확정하지 않았습니다. 메시지 원문과 콜백 토큰을 저장하지 않으므로 처리 중 장애의 자동 복구·재전송에도 한계가 있습니다.

가장 아쉬운 점은 개별 기능의 구현과 검증을 실제 고객의 전체 상담 흐름 검증으로 충분히 확장하지 못한 것입니다. 후속 개선에서는 미검증 시나리오의 종단 검증, 장시간 응답 안정성, 첨부 입력 지원을 우선하고자 합니다.
