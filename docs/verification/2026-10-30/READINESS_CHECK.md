## 3. 새 문제

### [V-008 / P1 · 결정 대기] 결과 불확실 쓰기 1건이 그 사용자의 모든 쓰기를 24시간 잠금
관련 요구사항: 개발자 운영 방침(쓰기 재실행 차단) ↔ R-02 대회 액션 정상 동작  
검증 버전·시각: conversation-store.mjs 9A2CCD60B2FD / 2026-10-30  
재현: repro-v2.mjs J2. `cancel` 쓰기가 네트워크 오류로 불확실 → 23시간 뒤 다른 쓰기 `book` 요청 → execute 0회, "결과를 확인하지 못했습니다" 응답. `/초기화` 후에도 동일(J2b)  
근거: `src/conversation-store.mjs:48` 미해결 `unknown` 기록이 하나라도 있으면 `locked`. `:50` 보존 24시간. 잠금을 푸는 경로가 없음  
심사 영향(추정): 심사자 한 명이 쓰기 도중 시간 초과나 일시 장애를 한 번 겪으면, 그 계정으로는 이후 모든 쓰기 시나리오가 하루 동안 실패한다  
안전성: 중복 쓰기 방지 측면에서는 의도대로 동작(잘못된 동작 아님)  
필요한 결정: 안전과 사용성의 균형. 당일 API가 멱등 키나 상태 조회를 지원하는지에 따라 달라진다. 선택지 예시:
- 잠금 범위를 같은 액션(또는 같은 대상 리소스)으로 좁힌다
- 조회 도구로 상태를 확인하면 해당 기록을 `success`/`rejected`로 정리할 수 있게 한다
- 잠금 유지 시간을 짧게(예: 10~30분) 한다
- API가 멱등 키를 지원하면 같은 키로 재요청을 허용한다
권고: 대회 전에 위 값(보존 시간·잠금 범위)을 **설정값으로 바꿀 수 있게만** 준비하고, 당일 API 문서를 본 뒤 총괄자가 정한다  
재검증 조건: 결정한 범위 밖의 쓰기는 실행되고, 범위 안의 불확실 쓰기 재실행은 계속 차단됨

### [V-009 / P1 · 결정 대기] 같은 쓰기·같은 인자를 24시간 동안 다시 실행할 수 없음
재현: repro-v2.mjs J1. 성공한 `book {date:'11-01'}`을 10분 뒤 새 메시지로 다시 요청 → execute 0회, "같은 작업을 최근에 요청한 기록이 있어 다시 실행하지 않았습니다"  
심사 영향(추정): 심사자가 같은 시나리오를 반복하거나 "취소 후 다시 예약"처럼 정당하게 같은 요청을 다시 보내면 실패한다  
필요한 결정: V-008과 같다. 중복 판정 창(예: 수 분)과, 사용자가 "다시 실행"을 명시했을 때 확인 후 허용할지 여부
