기준일: 2026-10-31 (KST). 출처: 사용자가 제공한 대회 기준과 후속 정정.
원문 추적: [최초 제공문과 후속 정정 전사](sources/legacy/COMPETITION_TRANSCRIPT.md). 개발 적용: [공통 응답·평가 가이드 프롬프트](prompts/COMPETITION_GUIDE.md).
**1·2·3번 항목은 4번 케이스 응답 정확도 점수에 따라 가중치를 적용받는다.** 원문의 5번 참조는 사용자 정정에 따라 적용하지 않는다. 구체적인 배점·가중치 공식은 제공되지 않았다.

이 문서는 향후 구현·프롬프트 수정·검증에 적용할 기준이다. 아래 개발 방침은 규정을 구현하기 위한 프로젝트 방침이며, 구현 완료를 의미하지 않는다. 과거 문서의 답변 800자·1,000자 준비값보다 이 문서의 500자 제한을 우선한다.

## 1. 평가 항목

|번호|평가 항목|평가 기준|개발 적용|
|---|---|---|---|
|1|에이전트 응답 속도(p95)|개별 말풍선 latency를 측정하며 빠를수록 높은 배점|전체 처리 경로의 지연을 줄이고 말풍선 단위 p95를 검증한다.|
|2|응답 메시지 평균 말풍선 수|케이스별 에이전트 응답 말풍선 수가 적을수록 높은 배점|한 번에 필요한 답을 전달하고 불필요한 인사·진행 알림·분할 전송을 줄인다.|
|3|말풍선당 평균 글자 수|응답 말풍선 하나에 담긴 평균 글자 수가 적을수록 높은 배점|결론·필수 근거·처리 결과·필요한 다음 행동 중심으로 간결하게 답한다.|
|4|케이스 응답 정확도|확인된 지식·근거, 고객 문의 맥락, 운영 정책에 부합하는지와 필요한 조회·처리·이관의 수행 여부 및 정확성|필수 액션 서버 API를 정확한 인자로 실행하고 확인한 결과만 안내한다.|

**정확도를 우선 확보한 뒤 속도·말풍선 수·글자 수를 최적화한다.** 간결함이나 속도를 위해 필수 조회·처리·이관, 정책 안내 또는 필요한 확인 질문을 생략하지 않는다. 정량적인 종합 점수는 공식 가중치가 없으므로 추정하지 않는다.

## 2. 종료·제외·재진행 규칙

|상황|대회 기준|
|---|---|
|SimpleText 이외 응답|해당 케이스를 종료하고 SimpleText 메시지까지만 평가한다.|
|60초 이상 무응답|케이스를 종료하고 직전 메시지까지만 평가한다.|
|응답 메시지 10건 도달|케이스당 최대 10건이며, 10번째 메시지까지 평가 후 종료한다.|
|답변 분할 전송|나눠 보낸 말풍선은 각각 1건으로 계산한다.|
|말풍선당 500자 초과|해당 답변은 평가에서 제외되지만 응답 메시지 10건 한도에는 차감된다.|
|운영측 에러로 평가 중단|중단 직전 메시지에 이어서 재진행한다.|
|종합 점수 동점|최종 제출 완료 시각이 빠른 참가자를 우선한다.|

사용자 제공 형식 참고 링크: [카카오 SimpleText](https://developers.kakao.com/docs/ko/bot/rest-api#simple-text). 이 문서는 제공된 대회 기준을 정리한 것으로 해당 링크의 최신 본문 검증 기록은 아니다.

## 3. 구현 및 응답 작성 방침

1. 정상 답변·확인 질문·오류 안내를 포함한 모든 사용자 응답을 SimpleText로 전송한다.
2. 기본적으로 한 번의 응답을 한 말풍선으로 완성한다. 짧은 진행 알림으로 응답 건수를 낭비하지 않는다.
3. 모든 말풍선은 최종 전송 직전에 500자 이내인지 확인한다. 모델 지시만으로 제한 준수를 보장하지 않는다. 긴 답변은 핵심 내용을 보존하며 압축하고 자동 분할을 기본 대응으로 사용하지 않는다.
4. 공식 글자 수 산정 방식은 제공되지 않았다. 확인 전에는 공백·줄바꿈·말줄임표를 포함해 UTF-16 길이 500 이하를 보수적인 내부 기준으로 사용하고, 이모지·한글 결합 문자 경계를 보존한다. 이 내부 기준을 공식 산식으로 표현하지 않는다.
5. 입력 수신부터 모델 호출·액션 실행·최종 응답 전송까지 전체 시간 예산을 관리한다. 60초는 허용 목표가 아닌 케이스 종료 경계다. 전송 시간을 남겨 두고 실패 시에도 짧고 정확한 안내를 반환한다.
6. 필요한 정보를 한 번의 확인 질문에 모으되, 대화 맥락이나 조회로 이미 확인한 정보를 다시 묻지 않는다. 케이스당 10건은 사용자 입력 수나 API 호출 수가 아닌 에이전트 응답 말풍선 수다.
7. 조회·처리·이관 성공은 API 결과로 확인한 뒤 안내한다. 실패나 결과 불확실 상태를 성공으로 표현하지 않고, 쓰기 타임아웃 후 무조건 재시도하지 않는다.
8. 운영측 중단 후 이어지는 대화에서 문맥을 유지하고 이미 수행한 작업의 중복 실행을 방지한다. 공식 케이스 식별·재개 규격이 없으면 임의로 새 케이스를 판정하지 않는다.
9. 필수 검증을 마친 제출본은 지체 없이 제출할 수 있도록 준비한다. 동점 우선순위 때문에 정확도 검증을 생략하지 않는다.

## 4. 검증 및 기록 기준

- 정상 응답뿐 아니라 오류·거절·추가 질문도 SimpleText이며 500자 이하인지 확인한다.
- 499·500·501자, 공백·줄바꿈·이모지가 포함된 응답에서 길이 제한과 최종 전송 형태를 확인한다.
- 케이스별 말풍선 수, 각 말풍선 글자 수 및 지연 시간을 기록한다. 개인정보·비밀값·메시지 전문은 기록하지 않는다.
- 로컬 성능 점검은 입력 수신부터 전송 완료까지의 시간을 대용 지표로 사용하고, 이를 평가 서버의 실제 latency와 동일하다고 주장하지 않는다. p95 산정법·표본 수·측정 환경을 함께 기록한다. 공식 측정 시작·종료 지점과 집계 방식은 미제공이다.
- 10번째 응답 후 케이스 종료, 60초 무응답 종료, 비 SimpleText 종료, 500자 초과 답변 제외와 건수 차감을 검증 시나리오에 반영한다.
- 필수 조회·처리·이관, 정책 준수, 대화 맥락, API 실패·결과 불확실, 운영측 중단 후 재개를 검증한다.

## 5. 현 코드와의 차이 및 후속 작업

2026-10-31 문서화 시점의 코드 확인 결과다. 이 문서 작성으로 아래 구현을 변경하거나 배포하지 않았다.

- `src/agent.mjs`: 정상 답변을 1,000 UTF-16 단위로 자르므로 500자 제한 적용이 필요하다.
- `src/openai-model.mjs`: 최종 answer에 800자 이내를 지시하므로 500자 제한에 맞춰 조정이 필요하다. 내부 summary 길이와 사용자 말풍선 길이는 구분한다.
- `src/worker.mjs`: SimpleText 전송 구조가 존재한다. 모든 응답 경로의 최종 길이 검증 및 전체 전송 지연 검증은 별도로 수행한다.

구현 변경 시 위 차이를 해소하고 검증 결과를 기록한다. 기존 제출 후 변경 금지·운영 유지 방침은 해당 문서에 따라 적용한다.
