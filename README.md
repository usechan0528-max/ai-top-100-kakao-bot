## 실행

Windows에서는 `START_DEV.cmd`를 더블클릭하면 문법 검사·테스트·오프라인 데모가 실행됩니다. 세부 설정과 폴더 용도는 [개발 환경 사용 안내](docs/DEVELOPMENT_ENVIRONMENT.md)를 참고하세요. 시작 스크립트는 시스템의 Node 또는 Codex 내장 Node를 자동으로 찾습니다.

Node.js 20 이상에서 별도 패키지 설치 없이 실행합니다.

```powershell
.\START_DEV.cmd check
.\START_DEV.cmd demo
```

데모는 고정된 확인 문구를 반환하는 오프라인 예제입니다. 실제 AI 답변이나 카카오톡 연동을 의미하지 않습니다.

`node --test`와 package.json의 `test`·`test:watch`·`demo`는 PATH에 Node가 있을 때만 직접 사용할 수 있습니다. 일반 Windows 실행은 위 시작 스크립트를 기준으로 합니다.

## 쓰기 기록·잠금 설정 (V-008·V-009)

2026-10-30: [검증 문서 3장](docs/verification/2026-10-30/READINESS_CHECK.md)의 권고에 따라 설정을 분리했습니다. `wrangler.jsonc`의 `vars`에서 변경하며, 기본 동작은 유지합니다.

|설정|기본값|의미|
|---|---|---|
|`WRITE_RECORD_TTL_MS`|`"86400000"` (24시간)|쓰기 시도 시점부터 성공·거절·결과 불확실 기록을 보존하는 시간(밀리초, 양의 안전한 정수)|
|`WRITE_LOCK_SCOPE`|`"user"`|현재 사용자+채팅방 저장소의 모든 쓰기 잠금. `"action"`으로 설정하면 같은 액션 이름의 쓰기만 잠금(인자가 달라도 잠금)|

예를 들어 10분 보존·같은 액션만 잠금은 `"WRITE_RECORD_TTL_MS": "600000"`, `"WRITE_LOCK_SCOPE": "action"`입니다. 실제 변경값은 당일 API 사양 확인 후 결정합니다. 잘못된 설정은 초기화 단계에서 오류로 처리해 쓰기 실행을 막습니다.

보존 시간은 새로 생성되는 기록에 적용되며 기존 기록의 만료 시각을 바꾸지 않습니다. 성공·거절 기록도 만료 전에는 같은 액션·같은 인자의 재실행을 차단합니다. 잠금 범위는 같은 메시지의 후속 쓰기와 메시지 간 쓰기에 모두 적용하며, 조회는 계속 허용합니다. 과거 형식의 불확실 기록은 액션을 식별할 수 없어 만료 전까지 전체 쓰기를 잠급니다. `/초기화`는 쓰기 기록을 지우지 않으며 이벤트 중복 방지 24시간·대화 요약 30분도 그대로입니다.

로컬 검증: `START_DEV.cmd check` 문법 11개 파일·테스트 114/114·오프라인 데모 통과. 기본 24시간 유지, 설정 시간의 만료 경계, 액션별 잠금 범위, 재시작·기존 테이블 전환, 잘못된 설정 차단을 확인했습니다. 이 설정 분리 작업은 아직 배포하지 않았습니다.

## 연결 구조와 과거 서버 위치

현재 서버는 `src/worker.mjs`, 모델 어댑터는 `src/openai-model.mjs`, 저장 계층은 `src/conversation-store.mjs`입니다. 아래 과거 경로와 연결 방법은 초기 인계 설명이며 이미 적용된 부분의 현재 상태는 위 최신 기록을 우선합니다.

기존 서버 코드 위치:
`C:/Users/dldyd/Documents/Codex/2026-10-24/1-ai-11-1-1-api/outputs/kakao-worker/worker.mjs`

해당 서버는 별도 대화에서 작업 중이므로 여기서 수정하지 않았습니다. 최종 연결 시 `handleEvent`의 테스트 응답 생성 부분을 `runAgent` 호출로 교체합니다. 카카오의 요청 인증·메시지 수신·콜백 처리는 기존 서버에 맡깁니다. 배포 도구의 main 경로와 import 경로도 함께 확인합니다.

`runAgent`의 `model`에 실제 모델 API 어댑터를 전달하세요. 어댑터는 시스템 지침과 사용자 입력을 분리해서 보내고, 응답을 `{ type: 'answer', text }` 또는 `{ type: 'action', name, arguments }`로 검증·변환해야 합니다. 제공된 `signal`을 모델 요청에도 전달합니다. 공급자별 오류·사용량 제한을 처리하고 비밀키는 서버의 비밀 변수에만 저장합니다.

`runAgent({ context })`에는 서버가 인증한 사용자·채널·이벤트 정보를 전달합니다. 일반 객체 1단계, 최대 20개 키(키 64자), 값은 200자 이하 문자열·유한 숫자·불리언·null만 허용하고 복사·동결합니다. 문맥은 모델 입력에 자동 포함되지 않습니다.

`actions`에는 당일 확인한 도구만 등록합니다. 이름은 영문자로 시작하는 영숫자·밑줄·하이픈 64자 이내입니다. 각 도구는 `kind: 'read' | 'write'`, 설명·파라미터 스키마, `validate(args, context)`, `authorize(args, context)`, `execute(args, { signal, context })`를 제공합니다. 검증·권한 함수는 기다린 뒤 정확히 true여야 통과합니다. 입력 스키마 선언만으로 실제 필드 검사가 구현되지는 않습니다. `kind` 누락·잘못된 값은 쓰기로 취급합니다.

인자는 JSON 값 검사 후 깊은 복사·동결하여 검사 이후 바뀌지 않게 합니다. 한 실행에서 동일한 도구·동일 인자의 쓰기는 한 번만 시도합니다. 쓰기 결과가 불확실하면 이후 모든 쓰기를 막고 조회만 허용합니다. `AgentError('ACTION_NOT_EXECUTED')`는 공식 API 규격으로 미실행이 확실한 경우에만 액션이 던집니다. HTTP 오류 자체는 그 증거가 아닙니다. `pick(result)`으로 필요한 필드를 고른 뒤 결과 검사·길이 제한을 적용합니다.

`createActionClient`는 POST JSON과 Bearer 인증을 사용하는 예비 구조입니다. **대회 API 규격을 가정한 구현이 아닙니다.** 공개 문서에 맞춰 메서드·경로·인증·요청/응답 매핑을 수정해야 합니다. 외부 API 결과는 필요한 필드만 추려 모델에 전달하고 크기를 제한하세요. 쓰기 작업은 대회 API가 지원하는 경우에만 멱등 키를 사용합니다.

현재 기본 시간 제한 12초와 답변 길이 1,000자는 내부 준비값입니다. 카카오 공식 문서와 당일 제한을 확인한 후 조정해야 합니다. 시간 초과가 이미 실행된 외부 작업을 취소·복구한다는 보장은 없습니다. 따라서 타임아웃 후 쓰기 작업을 무조건 다시 실행하면 안 됩니다.

기본 쓰기 시작 여유는 3초(`minWriteBudgetMs`), 도구 결과 전체 항목 상한은 JSON 직렬화 기준 4,000 UTF-16 단위(`maxToolResultChars`)입니다. 모델·API 실제 제한과 구분합니다. 자세한 [실행 계약과 서버 통합 요청](docs/development/2026-10-24/CORE_CONTRACT.md)을 읽어 주세요.

**통합 시 필요 변경:** 서버는 반환값 `outcomeUnknown`을 확인하고 예외는 `userMessageFor(error)`로 안내해야 합니다. 정상 콜백을 이미 시도했다면 그 실패 뒤 오류 콜백을 추가하지 말고, 콜백 실패로 모델·액션을 재실행하지 않습니다. 신뢰 문맥, 이벤트 중복 방지, 요청량 제한, 에이전트+콜백의 공식 시간 예산, 상수 시간 비밀 비교도 서버 담당에게 요청합니다. 이 프로젝트 수정만으로 사용자가 실제 오류 답장을 받는다고 보장하지 않습니다.

**알려진 한계:** 대화 요약과 중복 이벤트·쓰기 차단은 Durable Objects에 구현됐습니다. 다만 실제 대회 액션은 아직 없으며, 메시지 원문·콜백 토큰을 저장하지 않으므로 처리 도중 프로세스가 중단되면 자동 복구하지 않습니다. 중복 차단이 정확히 한 번 성공을 보장하지는 않습니다. 보관 기간·호출 제한은 최신 운영 기록을 참고하세요.
